# 学習の足跡

通知表の所見づくりを手伝うアプリです（もとの名前は「所見メモ作成」。フォルダ名は `shoken-memo` のままです）。先生が児童ごとにメモを書き、そのメモから Claude に所見の案を5つずつ作ってもらい、勤務校の表記ルールで自動で校正します。

- **児童の名前は入れなくても使えます。** 入れた名前は、画面（名簿・見出し・一覧）と保存先の中だけで使います。
- AI（Claude）に渡るのは、先生がプロンプトをコピーして貼り付けたときの**出席番号とメモだけ**です。名簿の名前は、メモに入っていても「（名前）」に置きかえてから渡します。このアプリが自分で外に送ることはありません。
- 保存先は2通りあり、同じ画面がどちらでも動きます。
  - `index.html` をブラウザで開く → **このPCのブラウザ**に保存
  - Google Apps Script のウェブアプリとして開く → **スプレッドシート**に保存

## 使いかた（4つの手順）

| 手順 | 画面 | すること |
|---|---|---|
| 1 | メモを書く | 出席番号を選び、教科・生活・行事などのメモを書く。下の入力補助を押すと、カーソルの位置に語が入る |
| 2 | AIで案を作る | プロンプトを作ってコピー → Claude に貼る → 返ってきた文を貼り戻して「取り込む」。人数が多いときは「10人ずつ」などに分けられる |
| 3 | 案を選ぶ・直す | 5つの案から1つ選び、必要なら直す。校正結果が色付きで出て、「直す」で置き換えられる |
| 4 | 仕上げ・書き出し | クラス全体の校正結果・似ている所見を確かめ、CSV／テキスト／書き出しシート／印刷 |

右上の「設定」で、年度・学年・人数と、**学期ごとに今回書く種類**（所見・道徳所見・総合・外国語）を選びます。進み具合（完成・書きかけ）は、選んだ種類だけで数えます。

## 名簿のチェック

左の名簿で、所見ができたかどうかを**先生が項目ごとにチェック**します（自動では判定しません）。

- 子どもの見出しの下にある「□ 教科」「□ 生活」などを押すと、チェックが付きます。名簿のボタンの点が、項目ごとのチェックです。
- すべての項目にチェックが付くと、名簿のボタンが緑になります。途中ならだいだい色です。
- チェックする項目は「設定」で選べます（教科・生活・行事・伸び・道徳・総合・外国語）。初期値は 教科・生活・道徳・総合・外国語 で、道徳・総合・外国語はその学期にその種類を書くときだけ出ます。

## 「確認した」で指摘を消す

案を選ぶ画面の校正で出る「要修正」「注意」は、先生が確かめて「このままでよい」とした指摘を**「確認した」で消せます**。

- 1つずつ消すほか、「この文の指摘をすべて確認済みにする」で、まとめて消せます。
- 消した指摘は、案の判定・仕上げの数（要修正・注意）・上の手順の「要修正」にも数えません。
- 「表示に戻す」で、いつでも元に戻せます。文を直して別の指摘が出たときは、新しく表示されます。

## 名前

右上の「設定」または名簿の「名前を入れる」から、出席番号ごとに名前を入れられます（入れなくても使えます）。Excel の名前の列を、1行に1人で貼り付けることもできます。

- 名前を入れると、名簿が「番号・名前・チェックの点」の一覧になります。
- 仕上げ画面の「書き出し・印刷に名前を入れる」にチェックすると、CSV・テキスト・書き出しシート・印刷に名前の列が入ります。
- 所見の文に名簿の名前が入っていると、校正で「要修正」になります。
- スプレッドシート版では「名簿」シートに保存します。

## 道徳・総合・外国語のメモは、どの学期のものも使う

道徳所見・総合的な学習の記録・外国語活動の記録は、**1〜3学期に書いたメモをすべて集めて**案づくりに使います。たとえば2学期に書いた道徳のメモから、3学期の道徳所見のプロンプトを作れます。

- メモは、これまでどおり書いた学期に保存されます（データの形は変わらないので、前の版のメモもそのまま使えます）。
- プロンプトには「【道徳の姿（2学期）】…」のように、書いた学期を添えて載せます。
- メモ画面では、その欄の下に「ほかの学期に書いたメモ」を表示します（直すときは、その学期に切りかえます）。
- 名簿の「メモあり」や「まだ本文が無い児童」の判定も、ほかの学期のメモを数えます。
- 「所見のもと」（教科・生活・行事・伸び）と「その他メモ」は、これまでどおりその学期のメモだけを使います。
- どの欄を学期をまたいで使うかは、`rules/shoken-rules.js` の `memoFields` の `allTerms: true` で決めています。

## クラス全体の書き分け

同じ単元・同じ教科・同じ生活の項目（廊下歩行・あいさつ・掃除・給食・発表会など）の所見ばかりが並ばないように、3つの段階で工夫します。

- **同じ単元・同じ生活の項目は5人まで**（設定の「同じ単元・項目」で 3〜8人・しぼらない を選べます）。AIには「必ず守る」として伝え、上限に達した単元・項目はほかの子の案で取り上げないよう頼みます。
- 同じ教科・同じ書き出しは、クラスの3分の1までを目安にします（設定の「同じ教科・書き出し」）。
- **メモが似ている子**は、すでに採用したその子の文をプロンプトに載せ、「この文と書き出し・言い回し・文の組み立て・文末を変える」と頼みます。案を選ぶ画面でも、ほかの子の文と似ている案には「#3と似ている 58%」と出ます。

1. **AIへのお願い**（2 AIで案を作る）：プロンプトに「クラス全体での書き分け」を書き込みます。
   - すでに採用した所見での配分（例：国語科 12人、掃除 9人）と、目安に達しているもの
   - 何人もの所見に出てくる、まったく同じ言い回し
   - この回で、同じ単元・同じ話題・よく似たメモの子（例：「ごんぎつね」：#3・#7・#12）
   - 各児童の**案1**は、クラス全体で教科・話題がバラけるように選んだ組み合わせにしてもらう
   - 「10人ずつ」に分けて作っても、前の回で採用した所見を踏まえて書き分けてもらえる
   - メモに無い教科や話題は、配分のためでも持ち出さない（材料が1つの子は、言い方だけを変える）
2. **案を選ぶとき**（3 案を選ぶ・直す）：各案の下に、取り上げている教科・単元・生活の話題を小さく出します。クラスで目安を超えるものは、だいだい色で「国語科 12人」のように出ます。
3. **仕上げ**（4 仕上げ・書き出し）：教科・単元・生活や行事・書き出しの人数の表を出し、目安を超えているものを知らせます。案を切りかえると減らせる子がいれば「#5 案1 → 案3：国語科・掃除 → 算数科・給食」のように提案し、1人ずつ、またはまとめて切りかえられます。

- 目安は「設定」の「書き分けの目安」で選びます（クラスの4分の1・3分の1・半分まで、または使わない。初期値は3分の1）。少人数のクラスでも3人までは同じでよいことにしています。
- 話題として数える語は `rules/shoken-rules.js` の `variety.life` にあります。数えたい語があれば足してください（例：`{ label: "読書", words: ["読書"] }`）。
- 道徳所見は、内容項目を学年でそろえるきまりがあるため、教科・話題は数えず、書き出し（1文目）の重なりだけを見ます。
- メモ画面には「このメモの材料」（教科・単元・生活の話題）を出します。教科の姿と生活の姿を2つずつくらい書いておくと、配分を調整しやすくなります。

## ファイル

| ファイル | なかみ |
|---|---|
| `index.html` | 画面（見た目と動き） |
| `engine.js` | 校正・字数・似ている所見さがし・取り込みの読み取り（画面に依存しない部分） |
| `rules/shoken-rules.js` | 勤務校の所見ルール（表記・避ける表現・字数・道徳の型・お手本）。**ルールはここだけ直す** |
| `rules/course-of-study.js` | 学習指導要領（平成29年告示）の要旨と、所見に使える言い方 |
| `build-gas.js` | スプレッドシート用の画面 `gas/画面.html` を作る道具 |
| `gas/Code.gs` | スプレッドシート版のサーバー側 |
| `gas/画面.html` | スプレッドシート版の画面（自動生成。直接は直さない） |
| `tests/` | 自動テスト |

## スプレッドシート版の入れかた

1. 新しいスプレッドシートを作り、「拡張機能」→「Apps Script」を開く。
2. `gas/Code.gs` の中身を `コード.gs` にまるごと貼り付ける（最後の行が `ASHIATO-GS-END`）。
3. 「＋」→「HTML」で `画面` という名前のファイルを作り、`gas/画面.html` の中身をまるごと貼り付ける（最後の行が `ASHIATO-HTML-END`）。
4. 「デプロイ」→「新しいデプロイ」→ 種類「ウェブアプリ」。
   - 次のユーザーとして実行：**自分**
   - アクセスできるユーザー：**自分のみ**（いちばん安全。この画面に鍵はないので、「全員」にすると URL を知っている人がメモを読めます）

**前の版から入れかえるとき**は、`コード.gs` と `画面` の**両方**を同時に貼りかえてください（片方だけ新しいと保存がうまくいきません）。これまでのシートはそのまま読めます。

## この版で直したこと（3）

- 「生活・当番・係の姿」に書いた内容（廊下歩行・黒板消しなど）が所見に入っていても、「教科以外（生活・行事など）の所見が見あたりません」と出ていたのを直した。生活の項目の語を増やし、さらにその子の「生活・当番・係」「行事」のメモに書いた語が所見にあれば、教科以外の記述があるとみなす
- 同じ単元・同じ生活の項目は5人まで（設定で変えられる）。AIへのお願い・案ごとの札・仕上げの偏りの表と切りかえの提案が、この上限で動く
- メモが似ている子の採用済みの文をプロンプトに載せ、表現を変えるよう頼む。似ている案に印を付ける
- 名簿の状態を自動判定から、先生が項目ごとにつけるチェックに変えた
- 「要修正」「注意」を「確認した」で消せるようにした
- アプリの名前を「学習の足跡」にした
- 名前を入れられるようにした（入れなくてもよい。AIには渡さない）

## この版で直したこと

**1. 校正の誤検出**
- 「話し方」「表し方」「過ごし方」を「仕方」の誤りと判定し、「直す」で「話仕方」にしていたのを直した（「計算のし方」のような単独の「し方」だけを見る）
- 「出来事」「出来栄え」を「でき」の誤りと判定していたのを直した
- 「目で見る」を「てみる」に直してしまっていたのを直した（「〜て見る」だけを見る）
- 「話し合い、」（動詞）を「話合い」の誤りと判定していたのを直した（名詞のときだけ見る）
- 「たくさん」「お父さん」などを氏名と判定していたのを直した
- 「4,217人」の桁区切りを読点の誤りと判定していたのを直した（数字のルールと食い違っていた）
- 「地域社会」「体育大会」を教科名の「科」抜けと判定していたのを直した
- 見つかった文字と ng が違うとき（「3つ位」を「人くらい」にしてしまう等）は「直す」を出さない

**2. 「 」の中（子どもの言葉）**
- 「 」『 』の中は、表記・文末・言い換え・性格・教科名・固有名詞のチェックから外した。道徳所見の「〜守ります。」と記述していました、などが「要修正」にならない
- 氏名らしい表記・書式・数字・字数は、かっこの中も見る
- 道徳所見の文の数は、かっこの中の「。」を数えない

**3. ルール同士の食い違いと、それを見つけるテスト**
- お手本・道徳の型・例文・言い換え先・学習指導要領の「使える言い方」・入力補助の語を、校正にかけて error / warn が出ないことを確かめるテスト（`tests/rules.test.js`）を作った
- テストで見つかった食い違いを、勤務校の表記ルールに合わせて直した（算数の「既習の図形にならして」は書き間違いと思われるため、あわせて直した）

  | 場所 | もと | 直したあと |
  |---|---|---|
  | お手本・言い換え先 | みんなに声を掛け／みんなに声をかけ | 皆に声を掛け |
  | 道徳の例文（中） | 言葉遣い | 言葉づかい |
  | 道徳の例文（低） | 片づける／くわしく／みんなで使う | 片付ける／詳しく／皆で使う |
  | 道徳の例文（高） | みんなが納得 | 皆が納得 |
  | 道徳の1文目の型 | 積極的に意見を発表し…考えています。 | 進んで意見を発表し…考えることができました。 |
  | 道徳の1文目の型 | ふり返りながら | 振り返りながら |
  | 表記「上手く」の正しい表記 | うまく／上手に（どちらも避ける表現） | （具体的な言葉に） |
  | 指導要領・理科 | カードにくわしく書き | カードに詳しく書き |
  | 指導要領・算数 | 既習の計算を／既習の図形にならして | これまでの計算を／これまでに学習した図形をもとに |
  | 指導要領・社会・総合 | 社会の課題を | 世の中の課題を |
  | 指導要領・理科 | 理由をつけて | 理由を付けて |
  | 指導要領・体育 | うまくいくか | できるようになるか |
  | 指導要領・音楽 | 音楽をつくり | 短い曲をつくり |
  | 指導要領・特別活動 | みんなで | 皆で |

  勤務校の例文を直した箇所は、学校の意図と違っていれば `rules/shoken-rules.js` で戻してください（戻すとテストが知らせます）。
- 「○位になりました」（順位）を見つけるルールを足した（×のお手本が何も指摘されていなかった）
- 表記ルールに「くわしく→詳しく」「て見た→てみた」「て見ま→てみま」を足した（もとの「くわしい」「て見る」の活用形）。学校の一覧に無い語なので、不要なら消してください

**4. 進み具合を「今回書く種類」だけで数える**
- 設定で学期ごとに書く種類を選べるようにした。初期値は勤務校の R4 決定事項にそった学年×学期の組み合わせ（`rules/shoken-rules.js` の `defaultWrite`）
- これまでは4種類すべて書かないと「完成」にならず、所見だけの学期でもずっと黄色（要修正）だった

**5. 保存を1件ずつにする・上書きを防ぐ・人数を減らすときの警告**
- 前の保存が終わるまで次の保存を送らない。古い内容があとから届いて新しい内容を消すことがなくなった
- 保存番号を持たせ、ほかの端末やタブが先に保存していたら上書きせずに止めて、「向こうの内容を読み込む」か「この画面の内容で上書きする」かをたずねる
- 人数を減らすとき、入力済みの番号があれば知らせる。データは消さずに残し、人数を戻すとまた出てくる（これまでは、人数を減らしたまま開き直すと消えていた）
- スプレッドシートに書く文字を書式なしテキストにして、「=」で始まるメモが数式に、「10/5」が日付に化けないようにした
- 保存できなかったときは、右上の表示を押すと再試行できる。閉じる前に保存が残っていれば知らせる

**画面の構成とデザイン**
- 7つのタブを「1 メモを書く → 2 AIで案を作る → 3 案を選ぶ・直す → 4 仕上げ・書き出し」の4手順にまとめ、記録メモ帳とルールは右に分けた。手順の横に進み具合（メモ 12/32、完成 8/32、要修正 3）を出す
- 「プロンプトを作る」と「取り込み」を1画面に並べた。取り込んだら「3 案を選ぶ」へそのまま進める
- 「クラス全体の校正」「似ている組み合わせ」「一覧・書き出し」を「4 仕上げ」にまとめた。数字の箱を押すと要修正・未作成の子だけを出せる。「直す ›」で、その子の案を選ぶ画面へ行く（これまでメモ画面に飛んでいた）
- 名簿のボタンを状態ごとの色（未入力・メモあり・書きかけ・要修正・注意あり・完成）にし、凡例と集計をそろえた。前の子・次の子のボタンを付けた
- メモ画面は、今回書く種類の欄だけを上に出し、ほかの欄はたたんだ
- 案を選ぶ画面で、その子のメモを開いて見られるようにした
- すでに本文がある子に取り込むときは、「新しい案を後ろに足す／その子は取り込まない／置き換える」から選べる（これまでは手直しが黙って消えていた）
- プロンプトを「10人ずつ」などに分けて作れるようにした（返事が途中で切れるのを防ぐ）
- 年度・学年・人数・今回書く種類は「設定」の小窓にまとめ、上の帯には学期の切りかえだけを残した
- 「完全オフライン」の表示を、実際どおり「氏名は扱いません · 保存先：〜」にした。AIに貼り付ける前に、メモに本人が分かる事情が入っていないか確かめる注意を出した
- 入力のたびに全員分を校正し直していたのを、同じ文の結果は覚えておくようにした
- スマホの幅でも横にはみ出さない

## テスト

```bash
node --test shoken-memo/tests/rules.test.js shoken-memo/tests/engine.test.js shoken-memo/tests/server.test.js
```

画面のテスト（本物のブラウザで動かす。先に `node shoken-memo/build-gas.js` を実行する）：

```bash
NODE_PATH=$(npm root -g) node --test shoken-memo/tests/ui.test.js
```

ルール（`rules/*.js`）を直したら、`rules.test.js` でお手本と食い違っていないか確かめてから、`node shoken-memo/build-gas.js` で `gas/画面.html` を作り直してください。
